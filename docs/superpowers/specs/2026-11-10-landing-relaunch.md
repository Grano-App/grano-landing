## 1. Мета

Перетворити `grano-app.com` з брошури про застосунок на інструмент продажу Grano як системи для господарства. Сайт має:

1. Переконати власника господарства, якого привели партнер або дилер, що Grano закриває його потреби, а за продуктом стоїть агрофірма, якій він довіряє.
2. Зібрати заявку від господарства й передати її менеджеру з продажів.
3. Показувати, звідки прийшла заявка (UTM-мітки на посиланнях і QR).

## 3. Рішення

### 3.1 Аудиторія
Власник або керівник господарства на 200–2 000 га. Агрохолдинги — не ціль. У формі площу не питаємо й нікого не відсіюємо.

### 3.2 Позиціонування
**Повний цикл в одній системі: закупівля → поля й роботи → техніка й пальне.** Телефон — у полі, веб-кабінет — в офісі. Сайт іде від імені агрофірми партнера (ТОВ «Грано»): понад 10 років на ринку, понад 3 000 клієнтів, логотипи виробників.

Інноваційність показуємо конкретикою (датчики пального й алерти зливу, діагностика за фото), а не словом «інноваційний»: для власника 35–55 років абстрактне «інноваційний» нічого не доводить.

**Відкинуто:** «цифровий агроном» (дублює ADAM, звертається до агронома); «облік полів» як головне (OneSoil дає безкоштовно більше).

### 3.3 Що показуємо з продукту

| Функція | На сайті | Як подаємо |
| :-- | :-- | :-- |
| Техніка, пальне, телематика, контроль зливу | Так — головний блок | Абстрактно: без бренду датчиків і без цін. «Датчики ставимо й налаштовуємо самі» |
| Поля, операції, нагадування | Так | Частина циклу, не окрема цінність |
| Магазин насіння, ЗЗР, добрив | Так | Закупівля в агрофірми з доставкою |
| Лояльність / картка клієнта | Так | У блоці закупівлі |
| Діагностика за фото | Так | «Допоможе визначити ознаки хвороби», без обіцянки точного діагнозу |
| NDVI, фаза росту | **Ні** | Тимчасово вимкнено в продукті |
| Погода | Згадка | Не окрема функція |
| Запрошення людей у господарство | **Ні** | Статус невідомий |
| Заводська телематика (JDLink тощо) | **Ні** | — |

### 3.4 Головна дія та умови
- **Головна дія:** заявка (ім'я, телефон, господарство, область) → повідомлення в Telegram-чат → дзвонить менеджер з продажів, він же навчає.
- **Умови:** реєстрація й перший місяць — безкоштовно. Ціну не показуємо.
- **Реєстрація** відбувається в застосунку; веб-кабінет — тим самим акаунтом.
- **Значки сторів:** показуємо зі справжніми посиланнями (App Store `id6787681145`, Google Play `grano.app.com`) — рішення 2026-11-10, лістинги вже публічні. UTM додаємо на етапі 3.
- **Контакти:** телефон `+380 66 797 50 07`, пошта `support@grano-app.com` (скринька існує) — рішення 2026-11-10.

### 3.5 Довіра
- Блок «Хто за Grano»: агрофірма, 10+ років, 3 000+ клієнтів, логотипи виробників, регіони.
- Відгуки: до появи справжніх (3–4 господарства після пілоту) блоку немає. Статистика продукту — лише перевірювана.
- Кейсів із цифрами пілоту («спіймали N зливів») не публікуємо.

### 3.6 Вимірювання
- GA4: подія відправки форми й кліку на телефон.
- UTM на кожному посиланні й QR. Закріплення заявки за дилером не робимо.

### 3.7 Юридичне й публікація
- Privacy й Terms пише партнер. Політика має покривати геодані техніки з телематики.
- Деплой — Олексій.

## 5. Структура нової сторінки

1. Перший екран: повний цикл + «Залишити заявку» + рядок довіри (агрофірма, 10+ років, 3 000+ клієнтів).
2. Як зараз: зошит, Excel, чати у Viber, незрозуміло, куди пішло пальне.
3. Цикл: закупівля → поля й роботи → техніка й пальне.
4. Техніка й пальне — головний блок (скріншоти веб-кабінету).
5. Поля й роботи (телефон).
6. Закупівля: магазин, доставка, лояльність.
7. Діагностика за фото.
8. Хто за Grano.
9. Як підключитися: заявка → дзвінок менеджера → реєстрація → датчики ставимо самі → навчання. Перший місяць безкоштовно.
10. FAQ із реальних заперечень (дані, ціна, складність, інтернет у полі, датчики).
11. Форма заявки.

### 5.1 Стан веб-кабінету (код `fs-admin` / `fs-back-end` і локальна адмінка, 2026-11-10)

| Можливість | Стан зараз | Що з цим на сайті |
| :-- | :-- | :-- |
| Реєстр техніки, норми пального на вид роботи, бак кожної машини | Працює | Показуємо, скріншот |
| Картка машини: оброблено га, мотогодини, дні роботи, ремонт, пальне норма/факт, перевитрата, ₴/га, бак | Працює (мотогодини — ручне введення) | Головний скріншот блоку техніки |
| Поломка/ремонт з місцем і історією статусів | Працює; планового ТО з нагадуваннями немає | Показуємо ремонти; ТО — лише якщо буде в релізі |
| Склад пального: надходження, заправка, переміщення, списання, інвентаризація | Працює | Показуємо |
| Звіт по пальному: по техніці / полю / операції / ємності, норма vs факт, ₴/га, відхилення (перевитрата >10%, нестача, перелив, мінусовий залишок, надходження без документа) | Працює | Головний аргумент «куди пішло пальне» до появи датчиків |
| Операції: техніка, агрегат, оператор, га, мотогодини, пальне; прогноз пального на операцію | Працює | Показуємо |
| Поля на карті, мітки, публічне посилання | Працює | Показуємо |
| NDVI, фаза росту, погода, GDD | Працює в коді, вимкнено модулем | Не показуємо (§3.3) |
| «Аналітика полів» (врожайність по роках) | **Демо-дані** з плашкою «Демонстраційні дані» | Не показуємо |
| AI-асистент «Мокоша»: фото → проблема → препарат і доза → задача одним дотиком; відгук «помилилась» | Працює | Показуємо; назва «Мокоша» — так |
| Ролі: адмін, агроном, механік (завгар), комірник, бухгалтер, польовий працівник, перегляд | Працює; запрошень немає — працівника створює власник | Показуємо «кожному своя роль і доступ» |
| Телематика, трек, мотогодини й рівень з датчиків, автодетекція зливу, push-тривоги | **Немає в коді** (лише поля провайдера/ID пристрою, `equipment.entity.ts`: «no live ingest yet») | Обіцяємо як частину релізу, абстрактно (§3.3); скріншотів поки немає |
| Експорт звітів (Excel/PDF) | Немає | Не обіцяємо |

### 5.2 Звідки скріншоти
- **Веб-кабінет:** знято 2026-11-10 з локальної адмінки (`localhost:9000`) на окремому тестовому господарстві (акаунт власника `+380000000111`), заповненому демо-сезоном через API бекенду. Набір і опис даних — [docs/design/2026-11-10-landing-relaunch/](../../design/2026-11-10-landing-relaunch/README.md). Тестове `FARM-007` не використовуємо: там QA-дані.
- **Блок телематики:** скріншотів не буде до появи функції. До того — ілюстрація (схема «датчик → кабінет → сповіщення»), без вигаданого інтерфейсу.
- **Застосунок:** знято 2026-11-10 з білда `grano-app` `67cc7b6` на iOS-симуляторі, той самий акаунт і дані — [docs/design/2026-11-10-landing-relaunch/](../../design/2026-11-10-landing-relaunch/README.md). Старі `public/screens/*` замінимо на етапі 2.
- **Логотип:** справжній — `fs-admin/public/brands/grano/logo.png` («GRANO» з листком); на сайті зараз тимчасовий SVG «GRAN».
